## 3. InnerTube Protocol, Auth Separation & Gotchas (2026 Reality)
Keep all InnerTube `clientName`, `clientVersion`, `userAgent`, and `clientId` values in **one centralized config table** (`core/src/innertube/clients.rs`)—never scattered across parsers.

| Client | Auth Type Allowed | `n`/Sig JS? | PO Token? | Role |
| :--- | :--- | :--- | :--- | :--- |
| **`WEB_REMIX`** | Browser Cookies (`SAPISIDHASH`) OR Anonymous | Yes (strict) | Yes (bypassed by Premium) | **Primary Browse/Search/Home/Library/Next.** Last-resort playback fallback. |
| **`VISIONOS`** | Browser Cookies OR Anonymous | No (plain URLs) | Not currently | **Primary Playback.** Clean byte-rangeable stream URLs. |
| **`TV_SAMSUNG`** | **TV OAuth ONLY** (NEVER forward browser cookies) | Yes (TV JS) | Not required | **Playback Fallback (only if TV OAuth active).** |
| **`ANDROID_VR`** | **Anonymous ONLY** (no cookies) | No | Not required | **Anonymous Playback Fallback.** Blocks "Made for kids". |
| **`IOS`** | Anonymous ONLY (silently drops cookies) | No | Yes | **Avoid for logged-in users.** |

### Four Non-Negotiable Protocol Rules
1. **Strict Per-Client Auth Isolation:** Never send `WEB_REMIX` `SAPISIDHASH` cookies to `TV_SAMSUNG` or `ANDROID_VR`. Enforce auth mode in the client config struct (`AuthMode::Cookies`, `AuthMode::TvOAuth`, `AuthMode::AnonymousOnly`).
2. **Persist `X-Goog-Visitor-Id` (`visitorData`):** Capture `visitorData` from the first InnerTube response context, persist it in SQLite, and attach it on all subsequent anonymous/browse/player requests to prevent feed degradation and premature `403`s.
3. **Android WebView `403: disallowed_useragent` Fix:** When opening Google Sign-In in an Android WebView, strip `; wv` and set a standard mobile Chrome User-Agent. Capture `SAPISID`, `HSID`, `SSID`, `__Secure-3PAPISID`, `X-Goog-AuthUser`, `X-Goog-PageId` → compute `SAPISIDHASH` → store in OS Keystore/Keychain → destroy WebView immediately.
4. **Native QuickJS (`rquickjs` + QuickJS-NG `>= 0.12.0`):** Embedded natively in Rust strictly for `base.js` `n`-param/signature solving when non-ciphered clients fail. Cache extracted solver functions on disk keyed by player hash. Prefer Opus 774 (~256 kbps Premium) / Opus 251 (~128–160 kbps Free), fallback AAC 141/140.

## 4. Reliable 3-Tier Caching & Loopback Streaming Proxy
All audio playback routes through an in-process Rust **Loopback HTTP Streaming Proxy** (`http://127.0.0.1:<port>/stream/<video_id>?itag=<itag>`):
1. **Range-Aware Chunk Audio Cache:** 256 KB fixed chunks stored as atomic files (`.tmp` → `fsync` → `rename`) indexed in SQLite WAL. Supports instant arbitrary seeking, zero partial-file corruption on crash, offline replay, size-bounded LRU eviction (default 1 GB), and **transparent mid-stream `403` URL re-resolution** (handles ~6h TTL expiry and Wi-Fi↔5G handoffs without interrupting the player).
2. **SQLite WAL Metadata Cache (Stale-While-Revalidate):** Versioned schema (`user_version`). TTLs: Home `15m`, Search `5m`, Album/Playlist `1h`, Lyrics `30d`, Queue/History/Resume `infinite`, Stream URLs `<= 4h`. Corrupt entries self-heal by evicting and refetching.
3. **Two-Level Artwork Cache:** Memory LRU + atomic disk LRU (150 MB cap) keyed by `SHA256(url + size)`.
